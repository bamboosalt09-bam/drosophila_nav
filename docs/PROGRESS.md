# 진행 요약 (2026-10-03 기준)

자세한 근거와 숫자는 `docs/HANDOFF.md`, 연구 설계 원본은 `docs/master_handoff.md`.
이 문서는 흐름, 현재 상태, 남은 일만 정리한다.

## 1. 연구 목표와 전제

> 초파리가 예상 경로를 지정해주면 그걸 드론이 현실적인 조건 하에서 경로를 수정해 따라가는 거

- 초파리 커넥톰(MaleCNS)이 **가고 싶은 방향**을 내고, 드론이 **급선회나 충돌 위험이 있는 경로를 현실적인 범위에서 수정**해 따라간다 (구조 B).
- 센서는 최소화: 어안 카메라 1대 + 거리 센서 링(현재 24빔 고정).
- 최종 목표: 기존 인공지능과의 비교, 경로 효율 분석, 이후 3D.

## 3. 현재 구성

**입력 (커넥톰으로)**

| 입력 | 센서 → 뉴런 | 효과 (좌/우 자극, °/s) |
|---|---|---|
| 시각 | 어안 카메라 → 시각 투사뉴런 9,188개 | −22.7 / +13.5 (피함) |
| 위협 | 거리 센서 24빔 → LC4/LPLC2 311개 | −45.0 / +36.0 (피함) |
| 목표 단서 | 가장 밝은 비컨 방향 → PFL3 | +20.9 / −25.1 (다가감) |
| 시운동 반사 | 영상으로 추정한 자기 회전 → HS/H2 | 회전의 절반을 되돌림 |

출력: DNa01/02 좌우 차이 = 초파리의 선회 의도.

**드론 층**: 매 순간 여러 곡선 중 "초파리 의도와 가까우면서 3 m 앞이 막히지 않은" 곡선을 골라 제동 가능한 최고 속도로 비행. 후진 없음, 사방이 막혔을 때만 제자리 선회.

## 4. 확정된 것

- 거리 센서 0개로는 안전하지 않다 (네 방 모두 충돌).
- 조향 판독을 바꾸면 모든 입력의 효과를 다시 재야 한다 (ORN, 자이로가 이 때문에 조용히 죽어 있었다).
- 정면 벽은 좌우 대칭이라 커넥톰의 좌우 차이에 나타나지 않는다 → 벽 회피는 드론 층의 몫.
- 회로에는 재구성 데이터 때문에 약 −9 °/s의 오른쪽 편향이 남는다.

## 5. 남은 문제와 다음 할 일

1. **목표가 안 보일 때 기둥 열을 시계 방향으로 도는 고리** (선회의 98%가 오른쪽). 시운동 반사로도 안 풀렸다. 다음 단계: 고리 구간에서 선회 의도를 입력별(시각/위협/반사)로 쪼개 기록해 원인 확정.
2. 칸막이 뒤 6번째 비컨을 못 찾음 = 목표가 안 보일 때의 탐색 전략 부재.
3. 방 하나·비행 한 번씩의 결과뿐 → 4개 방 × 여러 출발 방향으로 제대로 평가.
4. "기존 인공지능"과의 비교 대상이 아직 없다 (지금은 지도 플래너와 밝기 추종 규칙뿐).
5. 이후: 경로 효율 분석, 3D 확장 (위아래 조향 신호가 회로에서 나오는지부터).
